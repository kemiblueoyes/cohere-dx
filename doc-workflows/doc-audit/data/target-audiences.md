# Cohere Dev Docs Target Audiences

## Audience 1: The Developer / Engineer
They're integrating Cohere's API into an application. They arrive with a specific task — make a RAG call, set up embeddings, stream a response — and want working code fast. They know Python or another supported SDK. They're comfortable reading API reference docs and scanning code samples.

### What They Need
Task-based guides, annotated code samples, error reference, prerequisite clarity.

## Audience 2: The Enterprise Architect / Technical Decision-Maker
This is the person evaluating Cohere for a production enterprise deployment. They care about deployment topology, compliance posture, data residency, and whether the platform fits their governance requirements. They may not write production code themselves, but they decide whether the team adopts Cohere at all.

### What They Need
Decision frameworks, comparison tables, plain-language explanations of tradeoffs, compliance mapping.

## Audience 3: The Enterprise Admin / Platform Operator
This person is responsible for configuring and maintaining Cohere in a production environment — setting safety modes, managing API keys, handling rate limits, overseeing deployment on AWS/Azure/OCI. They're technical but their job is operations, not feature development.

### What They Need
Configuration guides, behavioral explanation of safety controls, upgrade/deprecation paths, incident tracking.
